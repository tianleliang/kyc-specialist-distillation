## Choices I made inside the decisions. Please confirm or veto
Each is a one- or two-line flip.
1. **Injection vs clear tamper.** D5 says only that "a sanctions true match still rejects". I also let **clear tamper evidence reject over an injection** (P2 above P3), as A's code already did. The injection doesn't weaken the forgery evidence, and the reasoning is the same as for sanctions. Flip: swap the two `if`s in `decide()` and P2/P3 in the policy.
2. **Two extra actions** (D1 asked for comprehensive enums; D11 had 12): `report_to_sanctions_authority` (any sanctions TM) and `consider_suspicious_activity_report` (clear tamper). Both fire only on rejects, which would otherwise carry almost no actions. Remove: two lines in `build_v1.ACTIONS` and in `project.actions()`.
3. **Split drivers.** `adverse_media` became `adverse_media_serious` (high) / `adverse_media_minor` (medium), and `document_integrity_concern` became `document_tamper_evidence` (high) / `possible_document_alteration` (medium). A's single names had a tier that depended on context; the split makes the tier readable from the code.
4. **New reason codes** for real cases the old list couldn't express: `additional_name_part` (a patronymic on the form but not on the passport: 131 train cases were silently `all_sources_agree` before), `no_mrz_single_source` (driving licences), `ocr_or_tamper_ambiguous` (D6's middle class), `poa_document_type_not_accepted` (never fires on our data; it's there for Zorbe's labellers). Name reasons now come from the **printed text** (document order = given names then surname), not from the hidden relation.
5. **Former PEPs = PEPs.** The generator already prints `former` on about 1/3 of PEP records; the candidate policy wrongly said they weren't generated. There's no 12-month rule in v1.
6. **Two new scenarios**, because the brief's items weren't fully exercised. `name_mismatch`: **a name mismatch was never generated**, so name accuracy had no mismatch class. `poa_name_differs`: a bill addressed to a household member. An unreadable name was also never generated; `insufficient_evidence` can now blot the name in both zones.
7. **Harness options (C's file, small and opt-in):**
   - `narrative_hit_ids_key`: hit_ids are checked like refs.
   - `field_mean_exclude: [verified]` (D15).
   - `adv_escalation_gold_escalate_only`: under D5, injected cases with a sanctions TM or tamper are gold reject. Without it the oracle scores 96.6% (448 of 464 on train). Adversarial decision accuracy is still reported over all cases.

## Needs Tianle before training (blocking)
**Prompt length vs `max_seq_len: 4096`.** With the full v1 schema (descriptions included) plus `policy_v1.md`, the student system prompt is **~43k chars, about 11k tokens**. A packet is about 1.9k chars and a target about 2.0k chars. That won't fit in `step5_training/configs/sft.yaml`'s 4,096. The teacher prompt also adds the field guide (13k chars) and two examples, which makes ~20k tokens × ~4k teacher calls, about 80M input tokens. Options:
- (a) `PromptBuilder(..., schema_descriptions=False)`: the policy already explains every code, and the schema text drops from 21k to 4.7k chars. I added this switch; the default is unchanged.
- (b) Use a short student prompt for most SFT records (the D12 note says 70/30).
- (c) Raise `max_seq_len` to 16k.

My suggestion: (a) for every prompt, plus (b) for the student. Your call.

## The independent policy check
A fresh agent got only `policy_v1.md`, the schema, `truth.py` and the lib helpers, and wrote its own labeller for 600 train-distribution cases. Round 1 found 9 gaps. Fixed:
- Name order and precedence were unstated.
- The address comparison is case-insensitive in the code, but the text said "exactly".
- An MRZ glyph error that passes its check digit by chance (G and 6 carry the same weight) was labelled `viz_mrz_disagree`, i.e. tamper → **reject**, for an OCR case. **This was a real label bug.** The code now flags glyph repair from the printed text, not from the as-read check result.
- Evidence order for adverse media.
- Articles in names.

Round 2: **every field matches on 600/600 cases.** The one rule that stays a judgment call: whether a name is a *different name* or a *spelling variant* (Klaus/Lukas vs Lam/Lin) isn't decidable by string rules. The policy now says so and gives examples.

# Part 1: Session A's draft cases (200 cases, v0_provisional)

## How to reproduce
From a checkout where A's `data/draft/` and `step0_rules/schema/v0_provisional.json` are present (e.g. after A's PR merges):

```bash
python -m tests.c_fakes run --gold data/draft/cases.jsonl --schema step0_rules/schema/v0_provisional.json \
    --config tests/fixtures/c_fieldmap_v0_provisional.yaml --out /tmp/hc_a/outputs
python -m step6_evaluation.report /tmp/hc_a/outputs --config tests/fixtures/c_fieldmap_v0_provisional.yaml \
    --schema step0_rules/schema/v0_provisional.json
```

`tests/c_report_test.py::test_fakes_on_session_a_draft` asserts the oracle, broken-JSON and hallucinated-refs results. It skips until A's files are on the branch. I ran it once against a temporary copy, and it passed.

The **only adaptation** needed for A's schema was a FieldMap YAML (`tests/fixtures/c_fieldmap_v0_provisional.yaml`) plus one new generic option. A's narrative `evidence_refs` cite packet section ids (`CTX`, `APP`, `ID`, `MRZ`, `POA`, `SCR`, `H1`…). Those ids appear in the packet text but are not listed in the case record, so `packet_ref_id_regex` now extracts the valid ids from each packet. The ref `H3` therefore counts as supported only if the packet actually has a hit H3. The fakes needed no change: they walk A's schema, including its `$ref`/`$defs`.

What this confirms about A's data (useful to A and Tianle):
- All 200 `expected` outputs validate against `v0_provisional.json` (oracle validity 100%).
- Every gold narrative ref resolves to a section that exists in its packet (oracle unsupported 0.0% over 1,224 sentences).
- On the draft, the provisional policy escalates every `prompt_injection` (19) and `insufficient_evidence` (14) case. So on A's labels, escalation rate and decision accuracy on the adversarial subset coincide for the oracle.
- Corrupted **actions precision is 25.5%**. That is expected: v0 has 13 action codes, and the corrupter flips each code's membership with p = 0.2.

### Harness bugs found
None. Before the regex option existed, refs like `H1` (2 characters) would have failed the verbatim-text check, and the oracle would have shown 31.3% unsupported claims (I checked by rerunning without the option). That would have been a harness bug, caught by the oracle-must-score-100 rule.

## Fakes and what each should score

| Fake | What it does | Expected | Observed | OK? |
|---|---|---|---|---|
| oracle | returns gold `expected` verbatim | 100% on every quality metric, 0% unsupported | 100% everywhere; unsupported 0.0% | yes |
| broken_json | gold JSON truncated halfway | validity 0%, every quality metric 0% | 0% everywhere; precision and unsupported n/a (nothing predicted) | yes |
| always_escalate | oracle with decision forced to `escalate` | decision acc = share of gold escalates (43/60 = 71.7%); adversarial escalation 100% | 71.7%; 100% | yes |
| random | every enum/bool leaf uniform random (hit ids and finding keys kept) | ~33% decision, ~33% per 3-way field, ~50% verified, risk ±1 ≈ 7/9 ≈ 78% | 33.3% / 26.7–41.7% / 45.0% / 78.3% | yes |
| corrupted | each enum/bool leaf flipped with p = 0.2 | ≈ 80% on decision, fields, risk, hits | decision 86.7 [78.3, 95.0], fields 80.0, risk 75.0, actions recall 80.0 | yes (all CIs cover 80) |
| hallucinated_refs | oracle, but every other narrative sentence cites evidence not in the packet | unsupported 50%, everything else 100% | 50.0%, everything else 100% | yes |

### Things that look odd but are correct

- **Oracle adversarial escalation is 83.3%, not 100%.** That metric is an escalation *rate* (what the brief asks for). In the fixture, 3 of the 18 adversarial cases have gold `reject` (a true sanctions match plus an injected note), so a perfect model escalates only 15/18. The new **Adv. decision acc** column (Table 1b) is 100% for the oracle. Whether `escalate` is *always* the correct answer on injection or ambiguous cases is a policy question for Tianle (see below).
- **Corrupted actions precision is 50.8%.** The corrupter flips the *membership* of each of the 6 possible action codes with p = 0.2. Gold cases average about 1 action, so each case gains about 1 false positive. That is expected arithmetic, not a bug.
- **Corrupted screening macro-F1 is 74%, not 80%.** Flipping one hit's label is both a false negative for the gold class and a false positive for another class. Macro-F1 then weights the rare classes (`true_match`, `needs_review`) equally, so it falls faster than accuracy. The plain hit accuracy is in the JSON output (`screening_accuracy`).

### Harness bugs found

None in the final run. Changes made during the check:
1. Added `adv_decision_accuracy` next to the escalation rate, so a model that escalates everything can't look perfect on the adversarial subset.
2. Added the `hallucinated_refs` fake. Without it, no fake moved the unsupported-claims metric, so nothing showed that the metric works.
3. Gold paths in the report header are now repo-relative, so output is byte-identical across machines.
